# 协作与验证

统一执行 AGENTS.md。首次初始化直接 main；以后每个任务一个短期分支，一个工作区一个写入者。提交解释行为变化，不提交密钥、存档、备份、dist 或 node_modules。

```sh
npm ci
# 开发中：基础冒烟和针对性测试
npm test
npm run check:quick
# 提交前：按实际改动选择必须层级，含类型与构建
npm run check
```

CI 在 Node 22 与 24 上运行相同的分层规则，最多4个测试文件并行；仅PR/main push触发，同PR/分支旧运行可取消。新增行为提供可观察的验证；修改图形界面需要桌面/窄屏检查。PR 描述问题、改后行为、实际执行的验证层级、数据风险与回滚方式。没有成功部署和公网验证不能声称上线。

当前执行用户2026-10-17最新批准的[分层验证](VALIDATION.md)：普通修补不模拟真实比赛/赛季；比赛算法变化跑比赛专项；重大游戏流程跑完整业务赛季；二者同时变化才计算一次物理赛季。业务测试显式使用受控赛果，真实HTTP、SQLite和结算不替换。原有确定性、物理、赛季断言保留于专项目录，不能用fixture结果冒充物理证据。

先运行 `npm run check:plan` 核对分类。新增模块同步风险映射；自动识别范围外的重大流程在 `validation/major-flow/<任务名称>.json` 声明原因与本次运行文件，只能提高等级。每次验证记录 `work/validation/result.json`，CI上传对应Node版本证据；快测有待执行专项时不能作为最终验证。禁止为无关修改或定时任务重复模拟物理比赛。
