# 分层验证与开发耗时

0.10.0新增tactics/presets.mjs和matches/tactical-plan.mjs为真实比赛算法，配置/公共导出变化映射比赛专项；新增tests/match/tactics.test.mjs加入既有比赛单元清单，真实边路集成扩展intelligence-match。属于新模块风险映射维护，不改变分层、命令、并发、CI/PR或发布流程。


0.9.0新增的matches/ratings/为只读赛后统计公共入口，映射既有tests/player-ratings.test.mjs冒烟/针对性层，不导入或改变模拟器。若将它接入simulation等行为路径，依赖/函数变化仍触发比赛专项；若接入球员状态/资金结算，则按实际重大流程验证。此为新模块风险归属维护，原层级、命令、CI/PR与部署流程不变。

用户于2026-10-17明确要求执行耗时整改，并补充：“只有当有比赛算法改动时才模拟比赛”“游戏流程有重大改动时需要模拟赛季”“开发中的修修补补只执行基础冒烟测试，以及针对改动的点做针对性测试”。本规则取代过去每次都运行真实完整比赛与赛季的要求；独立分支、PR审查、冲突防护、备份及部署保护保留。

## 执行规则

| 改动与时机 | 自动执行 | 真实比赛 / 赛季 |
| --- | --- | --- |
| 日常迭代、修补 | 冒烟 + 对应模块测试；`check:quick`另含类型/构建 | 不跑完整比赛或赛季；若正在改算法，只增加相关物理/决策单元场景 |
| 普通改动的最终提交 / PR | 冒烟、对应模块、类型、构建；相关决策文档校验 | 没有比赛算法改动就不启用真实引擎 |
| 比赛算法或物理参数改动 | 上述检查 + 比赛单元、完整90分钟确定性/统计、短场景、真实worker恢复及HTTP比赛链路 | 跑比赛专项；不自动跑完整赛季 |
| 重大游戏流程改动 | 上述基础检查 + 完整14轮、奖金、换季、HTTP重启与备份恢复的业务赛季 | 真实游戏流程使用受控赛果，不计算无关物理轨迹 |
| 同时改算法和重大流程 | 比赛专项 + 赛季专项 | 同步业务赛季用真实引擎跑一次；HTTP持久化赛季仍用受控报告，避免重复物理赛季 |

“模拟赛季”分为真实业务流程验证与真实物理计算：前者执行生产的日历、计划、结算、出场/体能、财务和换季代码，替换的只有比赛报告；后者才逐场计算球员与足球。**只有算法发生变化，才启用后者。**没有定时重跑物理比赛或每日赛季的任务，也不因文档、测试搬迁、界面或健康标签修改而运行真实比赛。

重大流程按风险判断，包含赛程/杯赛推进、跨季、动作分发、状态迁移、持久任务接纳与原子结算。即使只有一行，破坏这些契约也按重大处理。普通UI、训练/转会局部修补和展示文字按对应模块验证。说明文字、注释和代码格式不视为算法变更；数字、分支、有效能力、阵形定义、规则、随机/限幅及Rapier版本变化按算法处理。

## 命令

```sh
# 开发中：冒烟与针对性测试；不会跑完整比赛或赛季
npm test
npm run check:quick

# 提交前：基于实际差异选择必须检查的层级
npm run check

# 先查看分类及原因，不执行测试
npm run check:plan

# 指定比较基线或提高流程风险等级
npm run check -- --base origin/main
npm run check -- --major-flow --reason "训练改为跨周任务，影响游戏日期推进"

# 诊断指定层级；match/season必须满足改动条件
npm run test:smoke
npm run test:business
npm run test:match
npm run test:season
```

默认基线是本分支与`origin/main`的共同祖先，包含已提交、暂存、未暂存和未忽略的新文件。主分支复核某次已提交改动时显式传`--base HEAD^`。CI使用PR的base SHA或main push的before SHA，并保留Node22/24。相同PR或分支新提交取消其旧验证，PR与main互不取消。手动工作流可指定base及重大流程判断，不能把自动识别出的算法风险降级。

自动识别使用可解析的代码结构，忽略注释/格式、已明确为展示用途的说明及错误文字；匹配具体函数和运行依赖，不只看目录名。重命名/移出引擎时，原文件删除与依赖连接变化仍属于算法改动。新增运行模块或行为时同步维护`scripts/validation-plan.mjs`的映射及策略测试，不能通过换路径降低验证。

对于自动映射以外的重大流程，提交独立文件`validation/major-flow/<任务名称>.json`，不同任务使用不同名称，避免多人覆盖：

```json
{
  "reason": "训练改为跨周任务，影响游戏日期推进",
  "files": ["packages/shared/modules/training/index.mjs"]
}
```

只读取本次新增/修改的声明；必须解释原因并指向本次修改的运行文件。声明只能提高等级。合并后旧声明不会让无关后续任务再次跑赛季。PR审查仍需核对实际影响，自动分类不能理解所有新的游戏设计。

## 测试隔离与覆盖

- `tests/*.test.mjs`：业务、冒烟和验证策略。业务进程显式预加载`tests/helpers/business-fixtures.mjs`，以Node自带模块mock提供受控报告；直接调用真实simulation/physics会报错。真实HTTP、SQLite、去重、权限、任务/检查点、压缩、原子结算和备份代码原样执行。
- `tests/match/`：真实物理/决策单元和真实比赛集成。无赛果fixture预加载，仍调用原来的生产引擎。0.7的真实HTTP比赛测试仅用显式`fast-broadcast-clock.mjs`预加载加速展示时钟，避免为发布门槛额外等待18分钟；不替换引擎/报告/RNG/物理，真实5×门槛另外由可控UTC单元与正常时钟HTTP/浏览器测试验证。新增文件必须加入明确的单元/场景列表，冒烟策略测试会拒绝遗漏。
- `tests/season/`：完整业务赛季与API跨重启赛季。只有同时涉及算法与重大流程时，`game-season`才不预加载fixture，成为唯一完整物理赛季。
- `tests/ASSERTION_MIGRATION.json`：原测试的搬迁记录；原确定性、进球/统计、物理、点球、worker恢复及赛季断言均保留。生日使用直接换季边界，杯赛直接构造开放轮次，避免仅为准备状态计算几十场无关比赛。

fixture报告带`testFixture:true`，轨迹标为测试数据，不能作为物理、胜率或统计校准证据。它只能由测试CLI显式预加载，生产代码没有环境变量、HTTP开关或存档字段可启用。未添加运行依赖；测试模块mock使用[Node自带功能](https://nodejs.org/download/release/v22.15.0/docs/api/test.html)，Node22/24均需CI验证。生产包不包含测试。

API快测保持真实限流，轮询采用较低频率；不能为加速测试关闭生产保护。测试数据目录由隔离临时目录承担，清理前验证绝对路径和前缀，不访问真实存档。

## 证据与维护

每次运行写`work/validation/result.json`，包含比较基线、改动文件、分类理由、选中的层级、实际执行阶段、耗时与退出码。CI上传每个Node版本的该记录；未执行的物理层级不能声称通过，`--quick`有待执行集成时会明确提示不能作为最终提交验证。

首次迁移本机测量：基础/业务49项通过约3.4秒；完整业务赛季10项通过约16.6秒；含类型、全部搬迁测试语法检查、构建和差异规划的检查总计约24.4秒。原60个场景全部有对应位置，物理场景断言保留；本次算法未变，真实比赛和物理赛季未执行。这是验证耗时，不是整个开发耗时，后续涉及算法的检查仍需实际计算时间。

相关算法、属性数据或参考图修改会运行`tests/decision-reference.test.mjs`，核对源码、Mermaid与SVG摘要；同次更新[决策图](../packages/shared/modules/matches/design/PLAYER_DECISION_MAP.md)、数值说明、导出、源码摘要和模块记录。源码注释/换行整理可能只需刷新摘要与核对记录，不代表比赛算法改变，也不触发真实比赛。

只有必须检查全过才能合并/发布；单次纯文档例外已成为历史记录，后续使用本分层规则。生产发布仍核对备份、健康、SHA和相关浏览器交互。普通界面/文案部署不为验收重复打一轮真实比赛；涉及比赛算法时再做相应真实试玩。首次拆分验证保留原已发布0.6.1回归证据，按本次授权不为未改变的算法重算旧全套物理赛季。
