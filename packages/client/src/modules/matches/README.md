# matches 界面模块

## 0.8.1 事件展示

event-filter.mjs是实时、物理回放和LegacyReplay的统一展示分类。关键事件使用明确名单，其他事件为其补集，未知类型默认归其他；全部动作保留原记录，裁判视图保持独立。进球/射门/扑救/犯规/红黄牌/越位/重要定位球/阶段与点球大战保留在关键事件；普通控球、传带球、拦截/争抢、失误、头球解围和普通出界重开归其他。换人/伤情仅兼容事件类型，当前引擎不生成，不代表已实现玩法。

四种筛选都必须先按当前播放时间截断；切换不能重置时钟、改变比分或球位置。事件不删除、不重算，旧报告无需迁移。增加新事件时在此模块明确分类，不能恢复“排除少数动作，剩余全是关键”的策略。相关测试tests/match-event-filter.test.mjs；按已批准的UI分层验证，不触发比赛模拟或决策图更新。

## 0.7.1 当前播放注意事项

live-clock.mjs仅处理浏览器展示时间，使用performance.now单调外推。收到报告或SSE时立刻记录receivedAt；异步画面完成时不得重盖接收时间。按broadcast.serverNow拒绝旧时钟/任务状态，连续运行时保留已知五倍速进度下界，避免网络抖动触发倒退后等待。真实buffering/finished仍接受服务端权威值，帧不足仍只画到已下载末帧。

useMatchJob并行取报告与增量帧，报告先只发布时钟摘要，帧解码后再发布匹配长度的report/data；中途到达的新SSE不能被迟到下载覆盖。PhysicalReplay用ref向稳定动画循环提供最新时钟与画面长度，不能每个网络包重建播放循环。不得以提高物理速度、预先显示未来比分或无限扩大轨迹缓冲来掩盖卡顿。

tests/live-clock.test.mjs覆盖迟到/乱序、变动延迟、真实缓冲/恢复、终场与跨场清理。界面变更还应以移动测试球检查零延迟、650ms画面请求延迟、650ms画面响应延迟的坐标停顿（连续>=100ms），并检查退出重入/刷新/赛后控制；使用显式测试CLI的受控报告，不计算真实物理。服务端/比赛算法与开发流程不变。

公共入口 index.ts；实现从原 components/pages 提取，旧路径保留兼容导出。领域规则由 shared/modules/matches 公共接口维护，不复制球员或比赛公式。修改此目录后同步 CHANGELOG.md，开发流程不变。

## 0.6.0 注意事项

新增useMatchJob/MatchTask，SSE重连与序号补片，实时画面12×默认、生成/观看双进度、缓冲/暂停/跟随最新/已生成历史进度和后台切换。PhysicalReplay兼容传入进行中轨迹；比分/事件按播放时间，统计只使用不晚于播放时刻的阶段快照并标记时间，避免全场剧透。后台结束可完整拖动/调速/射门跳转。注意客户端仅插值，不能补算物理或把已完成画面描述成仍在计算；旧报告继续原解码。

开发流程保持原样；本次只更改产品和运行实现。
新历史报告detailsStored为摘要，必须先由Replay读取/api/reports/:id，再交给PhysicalReplay；不能直接把空events/snapshots摘要当完整回放。实时任务已经携带完整阶段数据，不走历史详情加载。

0.6.1：球速包含垂直位移，球员速度仍为水平位移；按物理采样间隔计算，不乘播放倍率，cut重开帧不算瞬移速度。数值为5Hz区间平均，不等于物理瞬时峰值。
