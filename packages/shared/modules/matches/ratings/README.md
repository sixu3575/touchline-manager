# 赛后评分公开入口

普通带球距离沿用原有最多0.25分的贡献，新增加分来自真实成功过人，避免只靠里程或触球数量抬高评分。

## 评分3 · 2026-10-22

新比赛统计opta-conventional-2使用match-rating-3，真实成功过人与推进、位置防守、封堵/解围和丢球责任加入贡献。相同动作加分随次数递减；传球丢失通过成功率评价、过人失败与同次被断不重复扣分；旧保存的评分版本保持。公共playerStatisticsAt同时服务实时与回放。完整公式见[0.30统计设计](../design/STATISTICS_V0300.md)。下列原权重用于旧数据回退，非新版本全部公式。

index.mjs是纯统计公共入口，不导入物理/模拟器/Node/React，server与client只在完整报告可见后使用。算法版本match-rating-2，保存于playerRatings.version，独立于0.8.2-goal-net引擎和goal-net-1物理参数。

现实评分平台没有统一官方公式。这里参考[Sofascore评分框架](https://corporate.sofascore.com/about/rating)中的6.5基准、3–10范围和正负事件分类，以及[官方FAQ](https://sofascore.helpscoutdocs.com/article/50-sofascore-statistical-ratings-explained)的按位置/动作影响评价思路。以下是本游戏原创且公开的确定性权重，不是该平台未公开的商业算法。

0.15.1常规助攻与关键传球来源见[统计设计](../design/STATISTICS_V0151.md)：唯一shotId结果驱动，头球接球来源完整，补射/制造乌龙不混为正式助攻。旧评分保持，旧元数据缺失的有限证据回退仍有原时间窗口。

## 当前规则

原始分＝6.5＋下表各项；9分以上压缩为9+tanh(原始分−9)，再限制3–10，显示一位小数，避免大量普通贡献堆出满分。区间调整单独展示，分类先取两位小数，故可能有显示尾差。出场不足10分钟且无进球、助攻、红牌或乌龙时不评分。分钟取本场regulationDuration/clockScale及dismissedAt或已记录红牌时间；只计离场前的对方进球。没有随机项，不读取能力、身价、历史进球、号码、国籍或人气，也无直接胜负加分。

## 数据可信边界

- 只从本场snapshots/replay.players确定参与者，用performance的实际传球/成功抢断/推进距离及events作依据。未上场球员不虚构出场评分。
- 传球尝试的throughBalls、dribbleTouches、takeOn意图不是成功动作，不能直接当成功过人/关键传球。传球接收与射门链被断球、出界、犯规等中断后不能继续创造机会加分。
- save事件也包含普通卸球。优先对应对方近期射门，再按球队权威saves限制总数；旧报告没有该统计时仅接受有射门上下文的事件。没有PSxG数据，不宣称“预期扑救进球”。
- 进球、助攻与乌龙仅按保存标识归属，不解析事件文案猜责任。未记录解围、封堵、成功过人、致失球责任或扑救难度，不补造数据；xG缺失时不虚构精度。
- 点球大战事件minute>90不纳入常规赛后评分。正常比赛点球根据已记录penalty→shot→save/goal链识别。
- 旧报告数据较少标记limited，只使用已记录证据；快照仍有姓名/号码/位置，不能从当前阵容回填。评分与已有球员近期状态form独立，本次不改赛后能力/心理/资金结算。

## 保存与兼容

withPlayerRatings只返回带playerRatings的报告副本，已有带版本的评分保持原样。新完整战报在既有同一事务中连同评分压缩保存，state摘要剥离评分以控制轮询负载。历史压缩报告缺评分时，GET只生成响应，不改原BLOB/轨迹；旧示意报告由客户端同一轻量纯函数展示，不回放新引擎。

直播报告白名单在broadcast.finished之前不带playerRatings；界面也仅在终场显示。历史回放可直接查看完整评分，展开依据、两队切换与全场最高分标签不改变回放进度或比分。

对应tests/player-ratings.test.mjs涵盖归属、门将、短出场、纪律、权威计数、确定性/限幅、历史只读、事务回滚/隔离及终场门槛。新增纯统计目录映射到已有冒烟/针对性层；若未来把它接入simulation/球员状态/结算，必须同时取消只读排除并更新风险归属，按行为执行比赛或赛季层。开发流程不变。
