# 连续攻防与完整比赛重构方案

状态：2026-10-17 用户“就这样开发”批准本设计。0.6.0 按此实施，验证结果单列记录；数学参数是游戏模型，不宣称已拟合真实职业联赛。既有开发流程不变。

## 目标与顺序

先重做控球与传接，再完善组织/争抢，再统一完整90分钟时钟及后台计算，最后做分层统计验收。正式版本以完整比赛为目标；720秒短比赛只作为本地开发场景。现有球员30项属性继续使用，能力差异通过具体动作表现，不整体抬高球员数据。

## 1. 分离碰球、控球意图和实际控制

- lastTouch只服务最后触球、出界归属、折射和裁判，不直接等同球权。
- 独立记录接球、稳定控制、带球/受压护球、传球飞行、双方争夺、无人控制、死球阶段。
- 接球须确实发生合法有限范围接触，且卸力后有可继续处理的球，才算完成传球。碰到身体/挡出/停出脚下分别记事件。
- 控球意图允许合法下一触球前的短间隔，避免带球时刚超过1.3米就整队切回防守；它不能授权远距离施加踢球冲量。
- 球始终由物理世界运动；抢到松球须真正接近并完成控制。普通比赛时间、双方明确球权时间与争夺/无人控制时间分开计量。

## 2. 传球者与接球者共同完成动作

- 传前同时选择接球人、接球空间、接球时间窗、传球类型及到达速度。静止接球、迎球、顺势前插、一脚做球使用不同计划。
- 弃用所有短传至少14m/s的统一下限。候选力度依据距离、接球队员速度、压力与动作类型，结合现有草地阻力求得；短距离安全传递通常柔和，直塞/横穿防线/传中按需要更快。
- 只把可到达并可处理的接球窗口计入选择；预测考虑接球者当前速度、有限加速、转身时间和对手可达时间。
- 第一脚停球按下一动作、压力及边线选择方向；可停稳、让球、向空当卸力或一脚出球，不能默认向进攻方向踢出去。
- 对高速来球做连续接触检测/必要物理子步，处理球在两次20Hz采样间越过脚部范围的风险。冲量发生在实际接触处，不通过吸球或扩大无限接球半径解决。

## 3. 连续组织与实质对抗

- 区分后场组织、中场推进、最后三区、攻守转换。队友维持短传三角、回传点、宽度和纵深；有人前插时有人接应与保护球权。
- 决策评价接球后的可用路线、保有球权价值、推进、制造机会和失误代价。向前路线关闭时可以横传/回传；有明确机会时继续果断推进/射门，避免无限无威胁倒脚。
- 靠近边线时显式计入出界风险、停球余量和身体朝向，球员可减速、转身、回做；定位球和边线重开有相应的接应计划。
- 防守区分封线、施压、贴身争抢、保护身后与争二点球。抢断有时机、可达范围、实际触球及犯规后果；身体争夺影响位置和球的运动，不凭碰一下就直接转移稳定球权。
- 每次结束控球需可解释：主动传球、被抢断、被拦截、身体争夺、失控、射门或出界。受迫/非受迫丢球分开记录。

## 4. 完整比赛与免费VM成本

- 正式比赛以完整90分钟比赛秒为基础；活球过程实际推进，死球等待可快速结算并按耗时计入时钟。有效比赛时间独立统计；回放可跳过等待。
- 不用12分钟产生的计数冒充完整90分钟，也不将传球、射门或xG乘固定系数。回放事件、实际控制/射门与报表计数一致。
- 一轮仍只使用一个比赛worker和有界队列。后台任务显示进度，可恢复连接、退出观看后继续运行；较短计算片段各有超时，整场不再被当前单次120秒HTTP等待方式限制。
- 冻结输入阵容、能力、战术、种子与引擎/参数版本。检查点包含比赛时钟、随机数状态、物理状态、球员意图和累计事件；恢复后结果必须与不停机运行一致。
- 最终存档提交继续使用revision与requestId原子保护。计算失败或旧revision结果不得部分扣款、结算或覆盖新存档。开赛后固定本轮输入，同一种子恢复；离开页面不取消比赛，不提供看过比分后重开抽签的入口。玩家进度与计算任务临时数据分开。
- 优先减少远离球员的重复决策、缓存共享战术计算、跳过静止等待；球附近与实际接触保持必要精度。不能在同一场无提示混用近似赛果和物理回放。
- 当前实测一轮12分钟物理为46–69秒，直接扩大7.5倍粗估约6–9分钟；这不是承诺耗时。分段只改善等待/恢复，总计算量须单独优化和实测。沿用512MiB服务预算，发布前验证峰值余量。

## 4A. 两个比赛入口（用户补充需求）

赛前显示两个按钮：`实时观看（快进）`、`后台模拟`。它们创建或进入同一个比赛任务，只改变观看方式；都使用完整模拟、相同输入和种子、同一份轨迹及事件，最终只结算一次。

### 实时观看（快进）

- 点击后优先计算玩家本场，生成轨迹和事件片段后立即推送给观看页，不必等整轮或全场计算完才开始。
- 目标默认12×播放：完整90分钟画面在没有缓冲和额外时长时约7.5分钟；6–9分钟是观看目标，不是已验证的计算保证。原6–9分钟估算针对整轮四场计算，不能当成单场实测耗时。
- 保留短播放缓冲，分别显示模拟进度和观看进度。计算跟不上时显示缓冲或降低播放速度；不能生成尚未算出的未来画面。计算提前完成时标识“模拟已完成，正在播放剩余画面”。
- 比分、事件及个人/团队数据按当前播放时刻展示，不直接套用旧回放中一直显示全场统计的方式。完成后的完整战报另有入口。
- 可以暂停画面、追上最新画面、查看已生成片段，或转为后台模拟。暂停只暂停观看，服务器继续工作。不能拖到未生成的未来。
- 当前仍采用开赛前固定战术，本需求不附带临场换人或干预功能。

### 后台模拟

- 点击后显示计算进度，允许离开观看页或关闭浏览器。完成后在赛程/俱乐部动态显示“查看回放”和赛后统计。
- 重开浏览器凭原存档会话找回正在进行或已完成的任务。
- 完整回放支持进度拖动、暂停/继续、播放速度选择、关键事件跳转、球员详情与全场统计。
- 计算未结束时可以切入实时观看已生成的片段；换模式不创建第二场、不重新抽随机数、不改变赛果。

### 联赛结算与存档保护

- 玩家本场优先，其余场次由同一worker依次计算。场次输入和种子预先固定，不因计算顺序或有无观众改变结果。
- 玩家本场先结束时，可显示本场结果并标明“本轮结算中”；积分榜、资金、工资等在整轮完成后一次提交。
- 任务期间可浏览俱乐部；会改变本轮输入、资金或存档revision的操作暂缓，待本轮结算后继续。服务端同样保护，不能只靠按钮禁用。
- 同一存档/赛事/轮次的任务有持久化唯一约束，刷新、多标签页、重复点击、断线重连与观看模式切换均复用任务。
- 连接断开不终止模拟；服务器异常时从检查点恢复，客户端按片段序号续传并去重。失败展示可恢复状态，不形成半次结算。

### 传输与验证

- 沿用同源HTTP会话；进度和新增事件可用服务端事件流推送，轨迹按序获取压缩二进制片段，避免逐帧JSON造成内存/带宽浪费。只允许访问本存档任务和轨迹。
- 实时显示的片段就是最终回放保存的片段，不另跑客户端物理引擎；前端只插值绘制与控制播放。
- 必测：两种模式同输入结果/轨迹一致；实时首片段在模拟结束前可见；模式切换不重开；多标签页只结算一次；断线/刷新/服务恢复不丢片段；未生成区间不可跳转；直播统计只显示播放进度；旧回放继续兼容。
- UI与接口均在比赛内核/后台任务改造中一起实现，不先增加无法真正流式演算的装饰按钮。

## 5. 验收：先正确场景，再批量比赛

- 无防守、站稳的中等能力球员10米短传：以至少95%完成并稳定控制为初步工程目标；不是写入比赛的保底概率，也不声称来自真实赛事样本。距离、弱脚、压力和疲劳变化应产生合理差异。
- 控制同一防守条件与种子组，只改变进攻方相关能力：高传控能力应改善可控接球和持续传递；不能只把双方都加到90后凭一次比分下结论。
- 普通条件下能自然出现多段5–10脚同队连续传递；同时有失败、反抢与快速反击。不存在每段强制最少传球数。
- 固定受压、边线、二点球、接球转身与明晰射门场景；验证应出现的动作及有限物理接触，而非只检查不报错。
- 本地至少100场分层样本，覆盖不同水平、战术、体能和共同种子。分别统计同队控球链与两次死球间双方动作链、有效时间、出界来源、受迫/非受迫丢球、抢断/拦截/争夺、推进与禁区进入、射门位置/xG分布。
- 总传球量对照完整90分钟及明确统计口径；真实对照按水平/打法选取。普通样本仍普遍只有约100次且攻防以无压出界结束，则不能验收。不会通过人为补次数、禁止合法出界或强制凑比分通过检查。
- 保留既有种子可复现、规则边界、完整赛季、并发冲突、独立存档、重启和备份恢复检查。

## 6. 模块与数据边界

比赛目录拟新增possession、receiving、duels、clock、metrics等内部职责文件；传球/战术决策与physics继续分工，simulation负责推进编排。跨领域仍走公共index。server维护后台任务与检查点，client比赛模块展示进度、回放与完整统计。

新报告标识新引擎、参数和统计口径。历史赛果/轨迹不可重新推演；若新时钟或分段轨迹需要新的回放格式，则并行保留旧格式读取。任务持久表/格式变化提供迁移、备份与回退说明，不重置球队。

每个修改模块同步README/CHANGELOG及仓库相关文档。既有分支→检查→PR→部署流程保持原样，本方案改变的是游戏模拟和玩家等待方式。

## 实现契约与数学参数

- simulation.mjs 仍为唯一确定性20Hz编排；simulate耗尽createMatchSimulation生成器。默认5400物理秒，clockScale=1；短场仅本地测试选项，HTTP不接收。
- continuity.mjs分离controller、side、phase和lastTouch。2.6m内仅维持短时控球意图；踢球仍须有限脚部球体真正接触。carry意图可延续1.6+0.01×决策秒，且球员与球相对水平速度必须<3.5m/s。
- 普通地面传球目标到达速度v_a=clamp(4.5+0.17L+0.015Q,5,14)，初速sqrt(v_a²+2×0.8L)，飞行时间2L/(v_0+v_a)。0.8m/s²是草阻0.65和阻尼的近似规划值，轨迹仍由Rapier实际积分。高球仍按弹道而非地面公式。
- 接球候选按0.05秒扫描未来3秒，先扣反向速度/制动产生的转身时间，再用有限加速度和速度上限判定可达；迎球时留约0.48m触球间距。第一脚速度、方向误差取决于Q、来球相对速度和当前跑动；避开近身对手并向边线内侧卸力。
- 普通新接球准备时间0.65+0.012×(100−决策)秒；高停球/决策球员有一脚处理选项。观察期间可以真实短触球护球；身体站在球和威胁之间。传球价值同时考虑下一接应点，带球有有限意图延续奖励，风险变化时重新选择。
- 近场高速球采用2–8个物理子步，按球速×0.05/0.22选取；只在3m内有人且球速>6m/s时启用，在子步时刻检查同一个有限脚部形状，不放大碰球半径。
- 失败抢断至少1.6秒后才可再尝试，并暂时站回封堵位置；成功后被抢者需要恢复。静止站立试探失败不自动判犯规；实际快速接近或明显迟到的动作再进入原有基础犯规公式。
- 静止重开等待推进真实比赛时钟、体能和5Hz重复位置采样，不重复求解22人AI；进球入网的2.5秒轨迹仍计算物理。重开等待约10–25秒，计入死球时间；没有额外补时。
- report.continuity记录稳定控制、传球飞行、争夺、松球、死球时长及同队传球链、入禁区、死球原因/失误分类。两队之间死球段的传球数与同队球权链分开，统计不乘倍率。
- 比赛每60模拟秒产生一个持久片段；检查点包含Rapier世界快照/句柄、随机状态、球员意图、裁判状态、统计、事件和轨迹。报告/参数版本固定，完成比赛的原始二进制分段拼接后与一次性模拟一致。
- SSE只传任务索引；同会话HTTP获取gzip轨迹片段，序号去重，断线后补齐。实时12×是播放目标，生成不足会缓冲。30秒阶段快照用于不剧透的球队/球员统计，并显示快照时间。
- 历史正式报告只保留全场统计；阶段快照保存在最近3个比赛任务中，避免35场存档重复携带大量直播数据。历史positions-u16-v1与LegacyReplay解码方式保留。
- 门将反应门槛独立于战术扫描：0.12+(100−反应)/600秒；侧向扑救加速度响应为2.3+0.018×单刀防守。无近距离后卫保护的单刀，门将按球距×(0.25+0.003×单刀防守)主动缩短角度，深度限制2–8m；仍需手部实体接触。成功卸下低球建立自己的控制，扑出则恢复松球争夺。
- 射门的门将偏位项比较实际站位与球—球门中心连线上的合理位置，避免把正确防守近角误认为偏离门心的失位。xG是游戏机会估计，不决定实际进球，也不宣称真实数据拟合。
