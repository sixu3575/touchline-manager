# 0.14/0.15.1 比赛失衡审查与整改建议

日期：2026-10-19。**结论：现实性验收未通过；本文是诊断与待实施方案，不代表已修复或部署新算法。**

## 1. 证据范围与结论

当前生产代码为`22cf54a`，引擎`0.15.1-attribution`。该版主要修复统计归属，沿用0.14跑动体系。以普通初始球队、世界种子42、比赛种子999/1001运行四战术共8场当前引擎比赛，未加入观察球员。样本用于发现明显失衡，不足以估计整个联赛的分布或逐项因果贡献。

## 2. 跑动：最高速度、活动结构、统计误差分开看

99号本场实际位置为中锋，76.64分钟两黄罚下：37次射门、37次抢断尝试、18次抢断成功、10球（含2点球），不是仍只在边路的旧阵容。主队14:3后才罚下，之后再丢4球；红牌能解释部分尾段失球，不能解释此前17个进球。

- 最高速度32.33 km/h，本身在人类足球范围内。主/客外场峰值大致25.6–32.3 km/h；不能用统一降速掩盖问题。
- 现统计记99号11.655 km；5Hz轨迹保守剔除切帧后约12.692 km。按实际上场分钟折算，分别约13.68/14.90 km每90分钟。其他球员同样有距离偏差。
- 99号轨迹估计`>20 km/h`距离约5.770 km，`>25 km/h`约2.228 km，低速0–7 km/h只占距离约8.2%。这比总跑动更能说明持续高强度任务异常。
- 两队外场低速距离占比分别约11.3%/13.9%；普通球队8场球员平均约11.6%。UEFA位置参考中低速距离占比约38%–48%，高速距离也远低于上述极端负荷。总公里数看似接近现实，活动结构仍可完全失真。
- 客队十名外场体能全部到20下限。99号入场93、终场77.9，其他位置大量掉到20–40。体能会影响速度/技术，但没有短时疲劳、恢复及连续冲刺负荷状态；低体能也仍可不断申请冲刺。初始体能、耐力和上场时间同时影响消耗，不能只比较终场值。

**距离计量的确定问题**：`simulation.mjs/attemptTouch`在物理子步刷新`a.pos`，外层又把这个被覆盖的位置用作累计距离的上一个点。子步已走过的部分可能漏计。回放独立采样不依赖此基准。本场轨迹较统计多约8%–9%，8场普通球队平均多约10.7%。5Hz厘米量化、转弯弦长、切帧排除也有误差，轨迹估计不是绝对真值；修复时应以20Hz/子步独立积分与独立采样同时对账，不能简单乘1.1。

现实参考：[UEFA EURO 2024身体分析，第9–10页](https://editorial.uefa.com/resources/0297-1d4e3592fbf1-f11d4e1c826a-1000/uefa_euro_2024_physical_analysis_report_20250318094958.pdf)。90分钟部分、不含门将；按位置统计首发>70分钟，不能把这些精英数据当低级联赛硬性标准或单场上限。

## 3. 决策与模拟的相互放大

| 发现 | 源码证据/边界 | 建议 |
| --- | --- | --- |
| 控球短暂中断后组织状态跳变 | `continuity/updateContinuity`丢失controller；`positioning/teamRoles`主要依据owner/pendingPass判进攻，两者都无时双方都进入追球/防守分配 | 分离团队控球阶段、个人有效控制与争抢。保留短暂过渡记忆，不能保留虚假控球/远程触球 |
| 抢断抽签与争球路径不统一 | `simulation/attemptTouch`仅previous为对方稳定controller且双方<1.8m时进行抢断比较；previous为空时按争球/接球处理 | 明确控带保护、挑球可争、双方争球状态；丢失controller不能自动绕过对抗，也不能让旧持球者永远免抢 |
| 防守者有任务但防线缺乏整体约束 | 最近到达者每0.3秒选追球；中卫也可被选走，盯人仅剩余DEF承担；换人盯防只有有限偏好，中场多回模板 | 加压迫者、保护者、封线者分工，保留中卫/后腰保护，交接有稳定时间和补位，失误是局部事件 |
| 无球持续跑、高强度任务缺乏预算 | 指定接球/追球>7m即冲刺；盯防gap>4m或目标速度>5m/s即冲刺；前插/近远柱可持续冲刺 | 加位置死区、站定观察、跟随速度匹配、冲刺阶段/恢复；不把每次目标变化都当紧急追赶 |
| 带球路线估计与防守响应不对称 | `carrying`用3个采样点，持球人0反应，防守者另加反应；远点风险指数衰减，持续路线有额外偏好；实际抢断又是另一套质量比较 | 对齐双方到达/转身/恢复时间，计算次级协防与未来身体可达空间；保留真实空位快带，但进入压迫区必须重新评估 |
| 保球/降速组织的候选不足 | `decisions`主要在传、带、射中比较；许多时候没有持球观察/等待/回撤重组，短冷却反复行动 | 增加有效等待/护球/回做重组候选；控球战术强化安全三角和节奏变化，反击只在实际机会窗口提速 |
| 终结密度与效果同时偏高 | 本场67射，约29次动作质量记录为零压力（包含定位球）；8场普通球队49射左右也常见；内部xG不是进球抽签 | 单独校准射门散布、身体朝向、压力下准备、封堵和门将站位/反应/二点球。保持球由真实轨迹进门，不能用目标比分事后抹球 |

以上前两项与距离覆盖属于明确代码路径；它们分别贡献多少进球仍需隔离消融测试。防守重分配、风险估值和终结失衡是有源码/样本支持的整改方向，不能假称已逐项证明因果占比。

本场37/59次拦截、117/126次抢断尝试，说明防守接触并不少；弱点是抢下来后仍快速易手，以及防线没有限制反复进入射门区域。拦截与抢断采用本引擎定义，不能直接当作Opta/FIFA同名指标比较。

事件推导出的受控片段中位8.05秒、90分位21.6秒，有259次事件侧切换。这是代理指标，**不是精确稳定球权统计**；looseCarry=222也不是222次对手夺权。现实足球本来可以十几秒就换一次球权，异常不能仅由“几十秒一次”判断。观看5×只是把20比赛秒显示为4现实秒，所有校准使用比赛秒，不能调整物理时钟来伪装节奏。

## 4. 过去测过什么，为何没发现

0.14发布PR #22：[CI 39189808069](https://github.com/sixu3575/touchline-manager/actions/runs/39189808069) 的Node22/24通过。101项冒烟/业务、38项比赛单元、14项真实比赛/检查点/worker/HTTP集成，以及类型/构建；本地记录约201秒，CI检查分别约325/312秒（含阶段，不含全部排队时间）。有完整90分钟确定性比赛，也有3秒快慢追防、短时连续接球、死球和庆祝场景。

但断言主要检查相同种子可复现、时间/轨迹长度、比分等于进球事件、速度上限、体能范围、恢复和事务正确。`energy>=20`会让全队到下限仍然通过；“快人领先慢人”并不约束全场冲刺累计量；进球事件与比分一致，也不约束一场能否进21球。

0.6.0曾做100场独立校准，其默认球员平均传球531、总进球3.35等数字属于旧引擎。那份离线报告没有成为每版现实性门槛；后续也未把当前完整比赛统计归档、对比并形成阻断。这是验收设计不足，不是用户看错，也不是没有运行任何比赛。0.15.1的统计归属测试通过同样不能证明0.14运动体系已经合理。

## 5. 建议实施顺序与验收

1. **先补测量**：独立距离积分；按实际速度统计五区距离/时间、瞬时及持续速度、冲刺段；稳定球权片段、团队阶段、对抗后球权、盯防责任与丢人机会。重启检查点/旧报告缺字段明确标缺，不伪补历史。
2. **修组织和争抢**：团队阶段过渡、统一争球/抢断边界、前锋压迫半径、中卫保护、后腰封线及盯防交接。先用小场景验证，再观察正常比赛是否减少无组织易手和空门机会。
3. **修活动结构**：站定/低速跟随、任务死区、短时负荷与恢复。验收空位仍可快带、快球员仍能甩开慢追兵，同时不再持续数公里高速跑。
4. **校准传带射与门将**：根据修好组织后的真实结果调整风险/等待/射门散布；区分独立机会与补射群。内部xG在此阶段与实际转化校准，不能反过来强制进球。
5. **同输入消融与分布复核**：冻结相同阵容/体能/战术/种子，分别开关上述修复组作诊断对比；正式版本无实验开关。四战术×两个种子最低8场，加超级球员/弱队/低体能/高低压迫专项；给均值、中位/P10/P90/极值，审查异常回放。8场是最低筛查，不是完整统计学验证。

每项实际算法变更同步维护PLAYER_DECISION_MAP对应节点、阈值、SVG和SOURCE_SNAPSHOT。本次只审查与增加验证工具，未改决策算法，原图不伪装成已修复的新机制。

验证实施和工程警戒线：[REALISM_VALIDATION.md](REALISM_VALIDATION.md)。不得通过削弱警戒线、换随机种子、抹掉异常球员或强制固定传球/比分比例使检查通过。后续若真实样本/定义需要修正阈值，必须列出处与前后差异供审查。
