# 0.19.2 赛中体能与关键爆发

比赛引擎`0.19.2-stamina`，参数`stamina-3`。基于既有activity短时冲刺恢复机制补上有限的紧急爆发，并把体能以赛中数值条呈现。球员决策偏好、射门选择、传球/带球权重、长期属性和比赛时钟均不改；常规冲刺受负荷/恢复限制，肾上腺素爆发每名球员每场最多一次。

## 两种体能状态

- `energy`是本场持续体能。跑动强度、是否活球、压迫和球员耐力影响消耗；它会折损后续身体与技术能力。球员面板中的“体能”直接显示该值。
- `activity.load`是近期高强度运动负荷。速度超过5.56m/s时累积，慢速移动/停歇时恢复。跑动速度超过20km/h持续至少0.8秒后进入至少约12秒的恢复；负荷达到0.78也会恢复。恢复期阻止常规冲刺，并限制快带速度。耐力高的球员负荷增长更慢、恢复时间更短。
- 球员面板另显示“爆发储备”，按负荷相对常规冲刺上限0.78换算。它区别于本场整体体能：冲刺储备见底时，球员仍可慢跑、站位、接应和正常处理球。

## 关键时刻的肾上腺素

仅当常规冲刺因负荷/恢复被禁止、球员确有关键跑动职责且本场尚未使用时触发。每名球员每场最多一次、仅给1.4秒冲刺权限；不会补充`energy`或清空`load`，所以爆发结束后仍须依靠原恢复机制才能再次正常冲刺。

关键情境限于：进攻三区/己方球门26米范围内，第一/第二追球人距松球8米内；进攻三区指定接球者距球8米内；被盯防球员带球在己方球门26米范围内、正以超过3.5m/s做威胁跑动，且盯防者距目标超过4米；被选的前插者在进攻纵深70米之后、距球24米内且离跑动目标超过9米。一般中场追球、常规接应、门将、普通站位和普通控球不触发。条件源自既有角色与球场位置，不做全队随机加速，也不修改战术/技术决策。

球员状态属于既有actor检查点，爆发剩余时间、冷却和次数随检查点恢复。状态更新使用固定20Hz物理步长与确定性条件，不读系统时钟或全局随机数。新参数版本阻止旧引擎任务从中途状态错误恢复；历史轨迹及比分保持原样。

## 体能条与直播隐私

选择球员后，实时比赛/回放显示整体体能和爆发储备两条整数百分比进度条。新比赛在0秒记录初始状态，此后每30个比赛秒保存一次；回放在相邻状态间插值，直播仅使用不晚于观众当前比赛时钟的快照。旧报告缺失爆发储备时不编造该项。

“回放节奏与射门分析”是开发者诊断，不是玩家统计：客户端不再加载/计算/显示分析表。`replay-analysis.mjs`只由比赛测试与`tests/tools/match-realism.mjs`内部工具使用；生成的对照文件写入本机验证目录，不出现在游戏回放或球员战报。对照工具还会记录球员终场爆发储备、短冲次数和肾上腺素触发次数，方便检视疲劳机制是否生效；服务端战报投影会剔除整组内部运动分区/爆发诊断。

后续新增的回放节奏、射门、跑动和现实性分析默认归入战报`diagnostics`命名空间，不进入玩家界面或公共战报。服务端公开投影递归移除`diagnostics`、`analysis`、`analytics`、`telemetry`、`debug`及既有内部运动字段；只有用户明确纳入的统计才添加到公开统计和对应玩家界面。赛中体能与爆发储备是本次明确要求的例外。

体能约束旨在减少同一球员反复高速追击和前插，缓和部分攻防转换；它不会强迫倒脚、减慢足球、改球员的射门意愿或保证传球链增长。0.19.0首轮八场检查发现通用8米追球平均触发约481次/场；限制为每人最多3次后，八场样本中20名外场球员全部触顶，约60次/场，仍然不是偶发。0.19.2再改为关键情境每人每场最多一次。实际节奏效果见[TEMPO_V0180.md](TEMPO_V0180.md)；如果连续控球仍然太短，应继续从持球执行/阵线间距定位原因，不能以体力条宣称问题已解决。
