# 底线控球与有效触球统计复核

生产引擎 `0.37.0-boundary-touch-statistics` / `boundary-touch-1`，2026-10-24部署，SHA `7334e59118679186e27753a4680e2191a913747c`。备份和生产核验见[发布记录](../../../../docs/OPERATIONS.md)。

## 发现

生产比赛第14分钟一名球员的旧版报表显示208次触球，其中194次来自连续带球。引擎每次真实脚触都会保留物理轨迹，却把约0.25秒一次的步态带球触点也累加进常规“触球”字段，因此该数字不是可与常规赛后触球统计比较的口径。旧口径的重复部分来自`dribbleTouches`，不代表194次独立接球或攻防决策。

同一生产版本重新出现连续带球越过底线。路线评分和`motorTouch`的初始期望速度都调用边界安全计算，但随后有限身体加速度/惯性会生成新的出球速度；`kick()`把这一最终速度直接施加给球，绕过了原先按期望速度得到的安全值。坐标没有边界墙，球仍按Rapier碰撞、草阻和真实脚触运动。

## 修复

每次带球脚触仍根据当前身体动量、可用制动、预判、盘带能力、脚触间隔与触点误差生成出球速度。然后仅针对场地边缘，再以当前球位置和下一脚触球间隔核对最终速度的法向分量，并按剩余刹停距离调整球速；此检查发生在真实脚形接触后的脚触冲量中，不拉回越线球、不设全场速度上限。来不及处理的高速失控球仍会出界，场地中央的速度和误差不变。

常规有效触球定义为球员控制来球、直接头球/抢断或主动完成传球/射门等处理；连续带球里重复的步态脚触不作为新的常规触球。物理带球触点仍累计在内部`dribbleTouches`，用于引擎诊断，不呈现在玩家比赛面板；带球推进距离、过人和丢失球权按原口径展示。旧引擎回放以“物理触点”标识，避免把历史高频字段误认成新版有效触球。历史结果不会重算。

## 回归覆盖

`execution.test.mjs`加入两端底线的长距离连续带球复现：高速运行并重复真实脚触25秒，球不能越过底线；旧有近边界测试继续验证来不及刹停时球仍可出界，确认没有隐形墙。开放场地的速度保持原样。四种战术各用999和1001种子运行八场作为算法比较；赛季模拟不适用，因为本次没有改赛季流程。验证结果追加于本文件及模块CHANGELOG。

## 验证结果

八场全部完成：4 pass、4 review、0 block，汇总无分布告警。四个review的唯一告警均为少数球员低速跑动距离占比超过宽松诊断区间；相同八个固定种子的0.36基线也有四场review，跑动模型没有纳入本次改动。与该基线相比，八场均值为每场3.25球（基线3.375）、29次射门（29.75）、543.3次球队传球（533.3）和8,806.9米外场总跑动（8,748.5）。比赛间随机结果有波动，样本只用于检测明显回归，不构成现实性认证。

完整`npm run check`已通过：类型检查、128项单元/业务测试、16项真实比赛集成、种子999现实性检查和生产构建。最后加入服务端`dribbleTouches`过滤及对应玩家隐私断言，并改用`carryDistance`控制展示后，DTO隐私测试、32项物理执行测试、决策图来源摘要核对通过；八场矩阵使用最终比赛算法运行。`check:plan`标记为仅比赛算法变更，不触发赛季。Node 22/24 CI及生产部署状态以操作日志为准。
