# 0.30 动作统计与评分

引擎 `0.30.0-statistics`，物理参数仍 `physiology-1`，统计 `opta-conventional-2`，评分 `match-rating-3`。`statistics.mjs`只观察已执行动作和真实球权；不读取随机数，不修改决策、战术、球速、跑速、射门概率或疲劳。JSON/SQLite schema3和轨迹格式不变，新比赛增加可选统计事件及检查点状态；旧比赛不重演、原评分保留。

## 事件来源与时间

每条`playerStat`包含本场单调statId、second、playerId、side和整数changes。它是展示与评分共用的动作计数，不加入关键/其他事件列表，也不公开后台拟真诊断。球员/球队终场汇总与该事件流严格守恒；直播用最近两个非未来快照中较早的performance作为计数基线，通过statisticsBaseSecond标记，并只传基线之后的计数增量；普通动作仍取尾部。快照边界以1e-6秒容差避免浮点时钟双记。若画面尚落后基线或缺少基线，计数显示未知并等待同步，不读取未来数字。归档保留完整计数事件。客户端与评分公共入口`ratings/playerStatisticsAt`去重并按画面second裁切；不再拿全场抢断终值显示早期回放。未知历史数据展示“未记录”，无传球时成功率为破折号，避免把0/0称为0%或100%。

真实抢断、过人、扑救可能要等后续结果确认。确认发生时计数，不提前把未完成动作当成功；occurredAt可保留起始动作时刻，不能绕过直播终场/防剧透门槛。稳定抱住球时可以立即结束射门归属；扑出后仍可能进球，需要等后续结果。头/脚/身体射门封堵通过相同球路投影判断，最终关键阻止进球的防守者获得封堵；门将稍碰后仍需后卫门线阻挡的情形不自动给门将扑救。

## 统计口径

参考[Stats Perform / Opta官方定义](https://www.statsperform.com/opta-event-definitions/)。不宣称包含Opta所有人工判读语义，空间阈值为本游戏可复现的工程识别参数。

| 数据          | 实际记录条件                                                                                                                                                       |
| ------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 传球/成功率   | 实际传递计尝试，本方其他球员实际控制或主动头球接到才计完成；完成/尝试乘100并取整数。解围不计传球；现有投掷重开仍采用游戏既有传递实现，不声称完整区分现实手抛边线球 |
| 抢断尝试      | 真实近身出脚对抗启动；围堵、盯人、陪跑不算                                                                                                                         |
| 抢断接触/成功 | 实际触球将球夺离受控对手后计接触；随后本人/队友控制球权才计成功。未控球时，只有边线球/球门球判给挑战方才算安全赢球；判给对手不算，角球本身也不等于安全赢球。未夺离的挑战失败单独记failedChallenges，区别于Opta的接触后lost tackle |
| 拦截          | 主动脚/头控制或处理对方有效飞行中的传球；不能把任何散球回收都算拦截                                                                                                |
| 挡传/回收     | 新身体接触切断对方传递记blockedPasses，同一传递同一防守者去重；折射后再获得球者记recoveries，避免重复计预判拦截                                                    |
| 封堵          | 实际阻止本来会入网的射门；按最终关键介入者归属，同次射门不为每个碰球人加一次封堵                                                                                   |
| 解围          | 后场无接收者的头球或clearance实际出球；不当作失败传球扣分                                                                                                          |
| 成功过人      | 实际takeOn触球、对手在推进路线前方且进入争抢距离，随后沿路线越过该对手并保持本人控球；空位推进、意图、每次带球触球均不直接增加成功过人                             |
| 丢失球权      | 已有控球/传递后交给对方控制或重开：分别记传球丢失、被断、停球失控、带出界；同次只记一次。失控后本方收回不记丢球；射门、正常解围、获得犯规不算丢球                  |
| 扑救          | 对方真实射正被门将任一身体部位阻止入网；普通接传中、接偏出球不记扑救；同次射门碰后仍进不记扑救                                                                     |

过人识别：取真实带球目的地的方向，对手沿路线在前方至少0.5m、横向偏离≤1.8m、初始距离≤4.5m。本人进入与该对手≤1.8m的实际争抢区后才记一次尝试。本人沿原路线超过对手0.8m、分离>1.8m、球前进≥1.5m，同时控制状态属于本人且人球≤2.6m，才给成功。连续触球不重复开始；12秒或分离>7m关闭过期观察，传射/死球/其他球员控制终止。本方主动传出可中止已开始的尝试，不等同被断，也不扣过人失败分。这些阈值只识别已发生动作，不改变动作结果。

周期时间线不重复保存完整控球阶段、传球链、跑动分区和防守诊断；完整诊断仅存最终报告，运行检查点仍保留完整状态。广播压缩表示携带内部broadcastCompactionVersion标记，后台续算复用已处理对象，公共投影剔除此标记。以上只减重复观察/序列化，不减少比赛步数、轨迹采样或计数证据。

## 评分3

仍是本游戏原创公式，参考[Sofascore公开说明](https://corporate.sofascore.com/about/rating)的按贡献/位置评价框架；不是其未公开算法。基准6.5，最终3–10，一位小数；9分以上用原有平滑压缩；各项贡献展示计算依据。进球、助攻、机会创造、传球效率、纪律、在场失球等原规则保留，新统计只对新比赛启用。旧评分版本不覆盖。

设L(x)=ln(1+x)，所有计数来自确认事件；不以属性或身价代替实战贡献。

- 过人与推进：`0.12 L(成功过人)+min(0.25, 推进米数×0.001)`。普通带球距离保留原有有限贡献，实际成功过人另加分；避免仅靠普通里程抬高评分。反复触球、只增加尝试不加分。
- 防守：位置倍率（GK0.8/DEF1.1/MID1/FWD0.85）×`[0.12 L(成功抢断)+0.10 L(拦截)+0.16 L(封堵)+0.06 L(解围)+0.05 L(挡传)+0.025 L(回收)]`，减去`min(0.3, 失败挑战×0.015)`。同类贡献越多，边际加分越小；没有为凑目标数据改变比赛行为。
- 扑救：`0.38 L(扑救)+min(0.8, 点球扑救×0.5)`，没有PSxG或扑救难度时不虚构难度修正。
- 丢球责任：被断每次−0.045，造成交出球权的停球失控每次−0.06，带出界每次−0.05；乌龙与越位沿原规则。传球丢失已通过传球成功率评价，不再重复扣丢球分；过人失败与同次被断不再双扣；停球晃了一下但保住球不罚丢球。
- 能力、球衣号码、国籍、最终胜负不直接加分。数据有限的历史报告沿旧规则只使用可靠证据；未记录过人/丢球不补造0。

## 验证与发布边界

2026-10-26复核发现，先前对任意边线球/球门球都按“安全出界”判定，未核对发球归属；挑战方没拿到发球权也会被误记成功，角球也可能被当作安全结果。现改为仅挑战方获得边线球/球门球时确认成功，角球不作为安全成功。定向测试覆盖发球归属两侧、角球、实际控球确认；本修正不改变场上行为或历史记录。

专项检查后续球权确认、头球拦截与解围、身体挡传、真实过人方向/保球/去重、丢球分类、同次失误去重、稳定扑救、最后关键封堵、直播事件尾部保留/未来隐藏、回放前后拖动、旧评分保持、检查点恢复及球队/个人/评分守恒。此次统计边界修正运行记账/评分定向测试，不触发真实比赛或赛季；没有改工作流/阈值/CI。

比赛物理和选择模型未改，不属于战术平衡调整。另用0.29同输入完整90分钟保存轨迹比对，核实坐标/比分/跑动/能量保持，并生成原有现实比较。现实中的原有传递/拦截分布偏差须记录，不能因为计数守恒就声称已完成全部拟真校准。旧引擎未完成任务（包括airing）须排空，停服一致备份并离机校验后切换；四场并发仍关闭。
