# 物理比赛引擎 v1 · 0.3.0

本实现依据用户的新要求：重做赛事模拟，以真实物理引擎计算球的轨迹，战术与球员参数控制跑动、决策。原 PLAYER_MATCH_MODEL_V1.md 为历史待审方案，其概率赛果结构未启用；不能将其中尚未实现的犯规、心理或事件系统描述为当前功能。开发流程保持不变。

## 可观察的行为

- 22 个有质量的球员胶囊体在 105×68 米球场持续移动；相互碰撞，按角色保持阵形、接应、追球、逼抢和盯人。下半场交换方向。
- 足球是独立刚体球，受重力、空气阻尼、草地阻力、反弹和碰撞影响；用脚、头部或门将手部的有限接触体积才能施加触球冲量。比赛进行时不将球粘在球员脚上，不按事件插值伪造飞行。
- 传球、带球和射门先产生目标速度，再由物理世界决定运动和接触。球完整越过球门线且在门框内才得分；不抽取“进球概率”。xG 只作机会描述，不能生成进球。
- 开球、进球后重开、半场、角球、球门球和界外球是明确死球状态，允许重新放球；保存 cut 标记，回放不把这些重置插值成飞行。
- 这仍是已计算结果的回放，不是可临场干预的直播。所有 AI 比赛使用相同物理引擎，只为本队保留轨迹。

## 物理与数值

Rapier 3D 0.21.0（固定依赖，Apache-2.0），服务端 WebAssembly。坐标x为球场长度，y为高度，z为宽度；单位米、秒、千克。固定步长Δt=0.05秒。足球半径0.11米、质量0.43千克，重力9.81 m/s²；开启连续碰撞检测。草地摩擦0.65，球/地面反弹系数0.6/0.48；滚动额外减速0.65 m/s²。

免费VM采用压缩比赛时钟：720秒连续物理过程对应5400秒游戏时间，clockScale=7.5；不缩放球速、重力或碰撞步长。半场在物理360秒切换。体能消耗按游戏时钟折算，跑动距离仍是实际物理距离，不伪造为职业球员90分钟里程。完整5400秒物理在VM上的四场结算超过120秒，因而采用此首版规则；这不是完整90分钟实时人体模拟。

触球冲量 J=m(v_target−v_current)。触球前必须由 Rapier intersectionPair 验证脚/头/手传感器与球相交；身体与球、门框的实体碰撞由求解器响应。球员运动使用有限加速度的水平冲量控制，锁定竖直平移和旋转；身体不与地面产生会阻塞水平移动的约束。球员不是完整骨骼人体，手脚是有限接触体积，不模拟关节和肢体动作。

地面传球按目标点和飞行时间求 v_x、v_z；高球的 v_y=(目标高度−当前高度+gT²/2)/T。引擎随后施加阻力、重力与碰撞，因此这个初始瞄准不保证到达。门线使用上一步与下一步球心的扫掠线段，检查整个球越线瞬间的位置；不能用一次位置接近球门判进球。

## 每项能力如何起作用

以下为当前实现的分工。s 为 1–100 属性，E 为当前体能；系数是待继续校准的游戏参数，并非现实球员测速或职业联赛拟合。

| 属性 | 当前简短作用与计算入口 |
| --- | --- |
| sprintSpeed 冲刺速度 | v_max=(4.7+0.037s)(0.7+0.003E) m/s。 |
| acceleration 爆发力 | a_max=(1.8+0.052s)(0.75+0.0025E) m/s²。 |
| agility 灵活 | 速度响应系数 r=0.3+0.007s；每步速度变化不超过 a_max Δt r；转向同样占用加速度。 |
| stamina 耐力 | 每物理秒消耗=7.5×(当前速度/8)×[0.006+0.00008(100−s)]；下限20；影响后续速度与加速，结算写回球员模块，再按现有赛程恢复。 |
| strength 力量 | 身体质量主体=60+0.3s kg（传感器附加少量密度质量）；射门初速20+0.11s、头球初速8+0.1s m/s。 |
| balance 平衡 | 困难停球后的重新行动冷却=0.35+(100−s)/200秒。 |
| finishing 终结 | 20米内射门的方向和高度误差；误差越大，实际轨迹越可能偏出门框。 |
| longShots 远射 | 决定尝试射门距离上限18+0.13s米；20米外射门改用此属性控制误差。 |
| passing 传球 | 地面传球目标误差幅度=(100−s)/100×(0.6+0.055L)米，L为传球距离；在此范围取种子随机误差。 |
| crossing 传中 | 边路高球采用本属性控制目标误差；高球按重力公式求初速度，不直接判传中成功。 |
| setPieces 定位球 | 角球、球门球和简化边线重开使用此属性控制第一次传球误差。没有自由球/犯规系统。 |
| firstTouch 停球 | 对方速度减本方速度的相对来球速度若高于5+0.17s m/s，先尝试卸力；仍可能停大或被抢。 |
| tackling 抢断 | 对方刚触过球时，控球阈值中的 s=0.65抢断+0.35停球；必须真实接触，不能隔空抢断。 |
| dribbling 盘带 | 有限脚下触球向前给球3.6+0.019s m/s，冷却0.28+(100−s)/300秒；同时减少横向误差并选择绕开近身对手。 |
| heading 头球 | 头部传感器与高球接触后可顶向前场或22米内攻门，目标横向误差幅度=0.06(100−s)米；不模拟跳跃争顶。 |
| vision 视野 | 可评估的队友最远距离=16+0.38s米。 |
| decisions 决策 | 传球候选效用噪声幅度=(100−s)/18；参与射门尝试选择与决策更新间隔。 |
| composure 镇定 | 近身压力 P=max(0,5−最近对手距离)；射门方向误差追加0.3P(1−s/100)米。 |
| positioning 防守站位 | 与配合共同缩小防守锚点偏差，不直接加全队防守分。 |
| offTheBall 无球跑动 | 缩小接应锚点偏差；前锋前插深度追加0.08s米，结合当前防线位置选择目标。不是完整越位判罚。 |
| teamwork 配合 | 锚点偏差尺度=[100−(站位或无球+配合)/2]/35米，乘固定种子个人方向偏差；影响阵形位置。 |
| marking 盯人 | 后卫锚点向具体前锋位置靠拢的权重=s/180，保留角色职责。 |
| anticipation 预判 | 追球前视时间=0.12+0.003(100−s)秒；门将预测落点阅读系数=0.65+0.0035s。 |
| concentration 专注 | 外场下一次目标决策间隔=0.1+[100−(专注+决策)/2]/180秒，再量化到0.3秒战术更新；低值反应更慢。 |
| reflexes 门将反应 | 来球后允许手部动作的反应延迟=0.1+(100−s)/180秒；预测到近门快速球时可使用受限加速扑救。 |
| handling 接球 | 来球速度低于8+0.17s m/s时尝试低速卸力，否则向前/侧面拍出；球继续独立运动。没有粘手或瞬移抱球。 |
| oneOnOnes 单刀 | 手部水平伸展上限=0.45+0.004s米，仍需手部传感器实际接触且在本方禁区内。 |
| aerialReach 制空 | 可尝试处理的球高上限=身高+0.008s米；另受实际手部接触体积的范围限制。 |
| command 指挥 | 缩小本方防守锚点误差，系数1−s/1000，最大10%；不增加扑救概率。 |
| distribution 出球 | 门将正常传球使用此项控制落点误差。 |

射门基础横向误差 ε=[0.4+0.065(100−射门属性)+0.3P(1−镇定/100)]×逆足修正；目标选球门左右侧，再在[−ε,+ε]内加入偏差。目标高度也随射门属性降低而分散。惯用双脚逆足修正为1，其他为1+(100−逆足)/400。球员身高决定身体和头部体积，以及门将手部可达范围。

年龄与职业态度继续影响训练；其余稳定人格、士气/信心、国籍、名字、价格、工资、名气、球衣号码没有新隐藏比赛加成。潜力仅限制成长。人格互动与心理影响仍需独立设计，不把历史待审方案整体当作已批准。

## 战术与决策

基础纵向锚点 GK=5、DEF=27、MID=49、FWD=70米，按角色人数横向分布。随球的位置平移、攻防阶段推进/回撤；只有最近一人追球，高压防守最多再增加一人；预定接球人提前迎球，其他球员保持接应与防线。队友近距离分离转向，余下接触由物理求解器处理。

控球偏好更早传递；反击压低无球位置、提高向前传递价值与长传选择；边路扩大宽度并选择高球传中；高/低压改变追球人数与防线深度。传球效用比较前进距离、队友空间、距离、沿线对方球员和决策噪声。射门需满足距离、中央角度、线路风险和决策选择，不根据赛前总评预设结果。

## 轨迹、服务和复现

- simulate 不读系统时钟/网络/数据库，也不改变输入；固定版本、输入、种子在同运行环境复现。WASM与初始化顺序固定；不承诺不同平台 JS 三角函数逐比特一致，历史回放始终读取保存的轨迹。
- 一场90游戏分钟包含720秒连续物理、14,400步；5Hz保存3,601帧。每帧49个小端uint16：22人(x+5,z+5)共44值，球(x+5,高度,z+5)3值，再加cut和最后触球者序号+1。位置以厘米量化，原始约353KB，在SQLite中gzip压缩，按需请求。metadata.duration和事件second为物理秒，minute及前端比赛时钟乘clockScale；无clockScale的早期轨迹按1兼容。
- 所有球队通过相同球员结算入口写回体能、出场、进球与近期状态；联赛轮末全部恢复8点，杯赛无额外恢复。AI不会获得永远满体能的优势。
- 服务端仅一个比赛worker、最多两个排队任务。结算先读revision并计算，再在同一事务复查revision/请求ID，写状态、轨迹和去重记录；过期计算结果不能覆盖并发修改。
- 球员/球/地面/门框是物理简化。当前没有越位裁判、犯规/红黄牌、换人、伤停、肢体骨骼、真实跳跃、弧线旋转或风场。边线球用脚下重开代替手抛；杯赛平局仍用原种子简化点球结算。上述限制不能包装为完整足球规则。
