# 赛事模块变更记录

## 2026-10-16 · 0.2.0

- 从 game.mjs 拆出独立目录和公共入口，保留原有玩法约束。
- 游戏日期与生日联动，市场球员同步更新年龄，新赛季不重复加龄。
- 验证：完整赛季、确定性、资金、API 并发、存档持久化和备份恢复；模块依赖检查纳入现有测试。
- 注意：晋级与奖金只能结算一次。每轮游戏日推进七天，下赛季从下一年 7 月 1 日开始；年龄通过 players 接口更新，不再直接加一。

## 0.3.0 · 2026-10-16

所有联赛场次均使用物理引擎，仅本队场次保存轨迹。抽出selectors/index.mjs为浏览器安全只读公共入口，服务端index继续兼容导出。赛季/奖金/杯赛规则和既有开发流程不变。

联赛和杯赛对AI也调用统一球员结算入口，按相同的赛末体能、出场和进球更新；所有球队赛后按既有每轮+8恢复，不再给AI无限满体能。完整赛季测试覆盖八队出场/体能。

## 0.4.0 · 2026-10-16

日期推进统一调用球员适应度；杯赛使用比赛模块knockout物理点球，不再掷币决胜，不重复统计常规进球。AI和本队使用同公式。

验证：沿用npm run check；新增approved-v1规则/迁移/确定性测试，发布另做浏览器与VM验证。

## 0.6.0 · 2026-10-17

新增createCompetitionPlan/settleCompetition：固定各场种子和输入，优先计算本队，其他场次顺序不影响随机；全轮报告齐备才统一结算体能、积分、收入和工资。同步advance/cup沿用同一计划与结算接口。注意本队先结束属于临时结果，不能提前写入积分/资金；拒绝缺场、重复或不匹配的报告。

验证：沿用npm run check；新增有限接球、跨中场检查点、任务去重/重启/隔离和完整赛季验证；另做100场分层校准、VM受限内存和桌面/窄屏验证。结果以发布记录为准。
兼容补充：同步advance/cup提交计划结果时保留既有俱乐部、球员和嵌套资料对象引用，继续满足applyAction原地更新契约；异步服务器仍结算独立DTO。
