观看与恢复契约：packages/shared/modules/matches/design/LIVE_BROADCAST_V070.md；入口在根PROJECT.md。改动同步本模块记录，遵守已批准的分层验证；开发流程不变。

- 轨迹压缩并独立保存，与存档/去重原子提交；新增会话隔离的二进制回放接口。

## 0.6.0 · 2026-10-17

以MatchJobs替换整轮阻塞任务池：一个worker、最多3个未结算任务、60模拟秒片段/45秒片段看门狗，检查点和进度持久化。相同存档/赛事轮次唯一，重复按钮加入原任务；关闭页面不取消，重启从原种子和检查点继续。暂停观看不暂停计算。计算期间服务端锁住存档写操作，读取/健康仍可用；赛果/轨迹/存档/revision/requestId与任务完成同事务提交。SSE仅发送索引，gzip二进制独立加载，Cookie授权，单存档最多4路观赛连接。任务闲置释放worker。注意引擎版本不一致必须停下恢复原release，禁止重抽；失败任务保留原输入并可重试。

验证：沿用npm run check；新增有限接球、跨中场检查点、任务去重/重启/隔离和完整赛季验证；另做100场分层校准、VM受限内存和桌面/窄屏验证。结果以发布记录为准。
运行补充：健康worker保留生成器和当前工作对象，不往返恢复/反压缩已提交检查点；新worker才接收恢复快照，使用期望tick保护一致性。独立轨迹缓冲转移避免复制；本队结束后的结算副本去掉直播timeline，减少重复存储。
事务补充：区分BEGIN失败与已开启事务的回滚，失败只更新任务状态并保留已提交work字节；存储暂忙延后恢复，失效worker继续计算前重发原检查点；未知压缩检查点单任务失败而不清空或重抽。
资源补充：等待旧worker完全退出后才接纳新worker，避免超时恢复或空闲收尾时短暂重叠占用512MiB预算；对应生命周期与事务边界测试通过。
