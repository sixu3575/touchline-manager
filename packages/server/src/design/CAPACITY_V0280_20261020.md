## 资源事实

实例元数据确认shape为`VM.Standard.E2.1.Micro`，系统可见2个逻辑CPU、952MiB内存、无swap。[Oracle现行免费资源说明](https://docs.oracle.com/en-us/iaas/Content/FreeTier/freetier_topic-Always_Free_Resources.htm)列出该型号基础算力为1/8 OCPU，可在条件允许时使用额外CPU资源。可见线程数不能代表两核持续算力。

原游戏服务MemoryMax=512MiB不变。首次隔离压测与生产计算同时运行后失联；没有取得上一启动的完整内核日志，不能把OOM写成已证实根因。重启后旧服务恢复一项未完成的0.27轮次，峰值触及512MiB；暂停后可用内存从约300MiB回升到627MiB。

已对完整数据库备份、离机核对SHA256及integrity_check。使用原33e0fb0代码在独立副本继续原检查点，65.7秒完成剩余AI比赛；仅对应存档revision/round各+1、新增4场结果和1次operation，其余27个存档与凭据不变。原数据库停止写入且SHA仍一致才原子恢复，保留原始库及离机备份。生产已恢复健康；这些真实存档和备份不入Git。

## 隔离短测

所有测试使用新建合成世界和独立SQLite目录，不推进生产赛程。临时systemd服务不启用开机启动，维护测试保留独立自动恢复原服务的短时计时器。软内存限制曾引发大量回收等待，后续移除该限制，仍保留硬限制及内存余量检查。测试配置不是生产配置。

本地Windows重构前4×90分钟、8读取端长测约262.7秒，C=82.24，RSS峰值391.3MiB，无缓冲、完整性ok、一次结算；不是目标VM证据。轻量入口后的本地4×300秒剖析C=102.4，RSS约255MiB；主线程约77%采样处于idle，worker主要消耗于真实模拟，其中Rapier步进约占总采样29%。该剖析只说明本地执行分布，不能当作VM的CPU利用率或9.66吞吐的单一归因。

## 判定

四场5×持续推进最低需要20个比赛秒/墙钟秒，方案验收目标为25。现机短测约9.7，未满足；单worker内四个上下文已实现，但改变调度顺序不能产生缺失的持续算力。两worker尚未在此机验收，400MiB预算已接近上缘，不能假定增加worker能解决。未运行不必要的三组完整VM长测，也不降低20Hz物理、5Hz轨迹或足球决策来掩盖失败。

## 可执行的资源迁移方案

优先检查同区域现有A1实例、配额和容量。Oracle现行文档的免费A1总额为2 OCPU/12GB；这是官方总额，账户已用配额、计费状态和区域实际供给必须在创建前核实。免费额度不足时停止，不自动使用收费资源。尚未创建新实例或产生费用。

1. 新建/复用足够资源的Ubuntu A1，使用用户已有公钥；准备Node22/24、原systemd服务和SQLite目录，不添加Docker/Redis。确认ARM运行依赖与真实worker恢复测试。
2. 在新实例隔离数据目录完成当前一场轨迹+三场AI，以及四场全轨迹的3组完整轮次；后者含8/16读取端、高事件/高压场景、空闲恢复，满足全部原吞吐/内存/时限与零OOM门槛。原VM仍可提供旧版游戏。
3. 排空旧版活跃任务，停止旧Node写入，取得新的离机一致备份；复制到新机并核验全部存档、历史BLOB与凭据。通过新版本迁移后先只允许维护验收，不开放双写。
4. 为保留玩家当前138.2.64.10的Cookie与访问地址，可让旧VM的Caddy反向代理到同VCN新机私网服务；3100只允许旧VM私网来源，继续由Caddy作为公网入口。也可另给新IP，但会涉及匿名会话迁移，不默认丢弃原登录存档。
5. 校验公网健康、部署SHA、原存档/战报/回放与真实观赛；迁移备份计时器，保留旧发布与数据库。新库表版本4不能直接交给旧33e0程序写入，回滚仍遵守停止写入、保护新进度和备份恢复规则。

若继续使用现机，则四场功能保持未发布；可另拆底线修复及单场内存改进发布。不得声称四场5×已可用。用户已选择本项，迁移预案暂不执行；后续若重启并发工作再重新核验资源。既有PR/CI/备份/发布流程不变。
